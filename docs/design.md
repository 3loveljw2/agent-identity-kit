# 设计哲学 · Agent Identity Kit

## 为什么做这个

一个 16 岁少年用 AI 从零搭系统的过程中发现：AI 很强，但**没有角色、没有边界、没有进化机制**。同一个 AI 一会儿是文案、一会儿是代码、一会儿是客服——每次都要重新教。于是把"人怎么组织团队"的模式搬给 AI：**给每个任务场景一个明确的身份**（能力 + 流程 + 交付物 + 边界）。

## 三个设计支柱

### 1. 身份即封装（Identity as Encapsulation）
每个 SKILL.md 是一个自包含的"角色胶囊"：身份声明（我是谁）+ 能力模型（会什么）+ 工作流程（怎么干）+ 交付物模板（交什么）+ 验收标准（怎么算好）+ 自主性设计（能自由到什么程度）。Agent 加载即上岗，不需要重新调教。

### 2. 自进化（Self-Evolution）
技能不是死的。每次真实任务都是进化的原料：留痕 → 蒸馏 → 版本 +1 → 公开记录（EVOLUTION.md）。**技能包本身演示了它要教的东西**（eat your own dog food——self-evolving-agent 的理念就是这个技能包的工作方式）。

### 3. 实证优先（Evidence-First）
2026 年 AI 内容泛滥，"看起来专业"不再稀缺，"被验证过"才稀缺。每个身份的能力必须挂到可核验的实证（测试/仓库/产物/记录）。**没有证据的能力，不写进技能包。**

## 与生态的关系

- **Agent Skills 标准**（2025-12 开放，Claude Code/Cursor/Codex/Gemini 兼容）：本技能包遵循该格式，复制即用
- **MCP**：身份技能是"角色层"，MCP 是"工具层"——本技能包定位角色层，可配合任意 MCP 工具使用
- **llms.txt / AGENTS.md**：AI 原生内容基础设施，本技能包全面采用

## 边界

- 技能包定义"怎么做"，不替人决定"做什么"——决策权永远在人
- 实证只记录可核验事实，不夸大、不编造
- 敏感信息永不入仓
